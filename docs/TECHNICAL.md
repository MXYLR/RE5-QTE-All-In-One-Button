# 技术说明（RE5 QTE All-In-One-Button）

本文记录实现所依赖的地址、结构与验证方式，便于在别的游戏版本上移植或在出问题时排查。
所有地址针对 **Steam 黄金版 1.2.0 的 `re5dx9.exe`（Enigma 1.31 壳，解包后映像基址
`0x00400000`，无 ASLR）**。

## 1. 挂钩点

游戏里所有屏幕按键提示由 `sActionButton::ButtonMgr`（每玩家一份，4 份，步长 `0x2D0`）
驱动。每个管理器有两个 action slot（`+0x230`、`+0x278`，各 `0x48` 字节），slot 有请求时
每帧调用：

```
ActionSlot::Check(request, pad, slot)      0x00766F00   (__thiscall, ret 8)
```

返回非 0 = “提示要的键按下了”。调用方随即消费请求（`request+0x0C = 1` 并触发动作）。
整份映像里对该函数的调用**只有一处**：

```
0x00767576   call 0x00766F00              在 ButtonMgr::checkAll（0x00767390）里
```

插件只改这 5 字节，把它变成 `call QteCheck`；需要放行时 `QteCheck` 仍调用原来的
`0x00766F00`（其它插件在该函数入口挂的钩子——例如 RE5PartnerAI——照常工作）。

安装前逐字节校验：

| 地址 | 期望字节 | 含义 |
|---|---|---|
| `0x0083A560` | `8B 44 24 04 D9 00` | 相机 SetLookAt 序言（只在解包后出现） |
| `0x00767390` | `83 EC 0C 53 55 56 8B D9` | `ButtonMgr::checkAll` 函数头 |
| `0x00766F00` | `53 56 8B F1 8B 46`（或 `E9`，被别的插件入口钩过） | 原生 Check |
| `0x00767576` | `E8 …` 且目标 = `0x00766F00`，后接 `3C 01 75` | 唯一调用点 + `cmp al,1/jne` |

## 2. 请求结构

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0x0C` | u8 | 1 = 已被接受（原函数立刻返回 0，插件同样跳过） |
| `+0x0D` | u8 | “已武装”标志，原函数会清零 |
| `+0x18` | u32 | 分类（slot 分类；普通提示 1，摇杆类 6） |
| `+0x1C` | u32 | Check 内第二层分类 |
| `+0x20` | u32 | 按钮类型，索引掩码表 `0xF58E50` 与图标表 `0xF590B8` |
| `+0x68` | u32 | stamp，区分被复用的请求对象 |
| `+0x6C` | u8 | RE3Controls 称 strict：QTE 提示常为 1（并非所有 QTE 都置位） |
| `+0x70` | u32 | 按玩家位的“已应答”标志 |
| `+0x74` | f32 | 剩余时间/脚本计时 |

掩码表 `0xF58E50`（u32[type]）：`1=X 0x8000`、`2=Y 0x1000`、`3=A 0x4000`、`4=B 0x2000`，
组合类型 13–19 为多键位。图标表 `0xF590B8`（u8[type]）：普通提示用字母编号
（`1→69 'E'`、`3→70 'F'`、`2→71 'G'`、`4→73 'I'`），QTE 类型用 33–55 / 97–100 的图标。

## 3. 判定规则

`QteCheck` 每帧对每个活跃请求：

1. 若 `[Auto] Enabled=1` 且命中自动规则（Grab/Combo/Special/Strict）→ 直接返回 1；
2. 否则若按下了 `Key` 且该请求属于 QTE（`strict`、两键以上、掩码 0、或玩家正被敌人抓取）
   → 返回 1。

`Grab` 判定：玩家动作 id（`ch+0x10E0`）必须是 `0x80000000`（事件动作），事件对象在
`ch+0x10F8` / `ch+0x1100`，其 `+0xC` 是发起者；发起者 DTI 属于敌人 / 敌人部件 / Boss
才算。DTI 常量与 `InEnemyGrab` 思路来自 **RE3Controls**（MIT，见第三方声明）。

## 4. 输入注入

部分剧情 QTE 不消费 `Check` 的返回值，而是脚本自己轮询 pad（威斯克战）。因此按 E 时除了
返回 1，还会把该提示的 `mask` 写进三处输入状态一帧：

- `Check` 收到的 PlayerPad（`+0x34` On、`+0x3C` Trg）；
- 角色自己的 PlayerPad（`[ch+0x2D64] + 0x708`）；
- 底层 sPad 设备 pad（`[0x1249C40] + 0x34 + i*0x2C0`，`+0x15C` On）。

游戏每帧重建这些状态，不会卡键。

## 5. 提示合并（显示 E）

QTE 组合提示会逐键画字母（`A+D`、`E+Q`）。插件对**能识别为 QTE** 的请求，在 Check 内把：

- `request+0x20` → 1（单 X 类型）；
- `request+0x18` → 1（请求分类，UI 画提示时读的就是它）；
- slot `+0x10` → 1（分类改为按键类）；
- slot `+0x18` → `0x8000`（X 掩码）；
- slot `+0x38` → 69（字母 E 图标）

于是提示变成单个 E，游戏等待的键也变成 X（键盘上就是 E）。只改槽位不改 `request+0x18` 时，
抓取挣脱仍然画 `A+D`——说明绘制路径读的是请求里的分类。

**注意**：早期版本曾全局改写掩码表/图标表，导致 `A+D 转动机关` 这类普通提示被一并改成
单 X（按 E 变成“停止转动”）。现在只对单条请求做合并，普通提示完全不动。

另外，普通提示上的字母（例如急救提示的 Q/B）是游戏按**按键绑定**画的，不是图标表；
插件改不了那个字母，只能通过改游戏键位设置来换。

## 5.1 额外类型（ExtraTypes）

`ExtraTypes` 里的类型会：

- 被 E 应答（强制接受 + 注入该提示的 mask），例如 `25` = 濒死时“连按急救”的提示（按 E 等于替你连按，提示文字也合并成 E）；
- 该类型的图标字节在启动时（并每 10 秒复查）写成 69（字母 E）。

注意这是**按类型**生效的共享表项，只应填确认过、不会与普通场景冲突的类型。

## 6. 插件加载器

插件原本由 dinput8 插件加载器从 `plugins\` 载入；该文件后来被 RE5Fix 的 dinput8 代理替换，
`plugins\` 不再被扫描。尝试过：

- `version.dll` 代理：不生效——进程在解析 exe 导入前就已经有系统 `version.dll`；
- `dsound.dll` 代理：生效。`re5dx9.exe` 按**序号 11** 导入 `DirectSoundCreate8`，
  代理保留系统导出序号 1–12，转发到同目录的 `dsound_orig.dll`（系统 dsound 的副本，
  因为同名 `LoadLibrary` 会拿回代理自己），并在首次调用时懒加载。

加载器在 DllMain 起线程，枚举 `plugins\*.dll` 并 `LoadLibrary`，日志写
`plugins\RE5Loader.log`。命名互斥体保证不会重复加载。

## 7. 测试

`tests\host_qte.c` 在进程内伪造游戏映像（段、函数头、调用点、假 Check、真实掩码表），
把 `GetAsyncKeyState` 重定向到本地假函数，覆盖：按键强制、strict 自动、两键 Combo、
掩码 0 的摇杆提示、state=1/used 位不重复触发、stock 返回值透传、Tap 边沿。

`tests\static_dsound.c` 以**静态导入**方式验证 `dsound.dll` 代理（和游戏同样的导入方式）：
转发返回 `DS_OK`，且 `plugins\RE5QTE.dll` 被加载。
